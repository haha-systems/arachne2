## Gotchas for follow-on tasks

- The legacy README describes Silk as agent-first and the language reference is broad, but Stage 0 classifies whole programs on two independent axes: runtime host dependence and compatibility priority. A standalone `silk run` does not install `task_input` or run the organism dispatch loop.
- Forty corpus recordings timed out in the documented five-second harness; 41 failed because `task_input` is only bound by organism dispatch; three depended on unavailable generic MCP. Those are different causes, not a single interpreter failure bucket.
- In-process organism builtins in `Interpreter.zig` are not equivalent to a live daemon/host integration. Empty traces for top-level `run` programs also do not show that handles/policies were exercised.
- Paper metrics are derived from deterministic fixtures and event logs. Keep workload, trace, formulas, provenance, safety counters, and non-claims connected when citing them.
- Many `docs/silk2/corpus/` filenames represent `.claude/worktrees/*` snapshots. The compatibility matrix marks generated duplicate snapshots abandoned; do not make those duplicate files new compatibility targets.
